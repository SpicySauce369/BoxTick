# 웹사이트 설계서

## 프로젝트명
**박스틱 (BoxTick)** — 포켓몬카드 시세 조회 & 카드팩 개봉 시뮬레이터

---

## 1. 시스템 구조

```
[브라우저]  HTML / CSS / JavaScript (fetch, Chart.js)
     │  HTTP (JSON)
     ▼
[Node.js + Express]  REST API · 세션 인증 · 권한 검사
     │  SQL
     ▼
[SQLite]  데이터 저장 (users, cards, price_history, posts ...)
```

- 프론트엔드는 정적 HTML 페이지로 구성하고, 데이터는 `fetch`로 REST API를 호출해 가져온다.
- 서버는 API와 정적 파일을 함께 제공한다.

## 2. 기술 스택

| 구분 | 기술 | 용도 |
|------|------|------|
| 서버 | Node.js, Express | 웹서버, REST API |
| DB | SQLite (better-sqlite3) | 데이터 저장 |
| 인증 | express-session | 세션 기반 로그인 |
| 보안 | bcrypt | 비밀번호 해시 |
| 프론트 | HTML, CSS, JavaScript | 화면 구성 |
| 테마 | CSS 변수 + localStorage | 라이트/다크 전환 |
| 차트 | Chart.js | 가격 변동 그래프 |
| 선택 | node-cron | 자동 시세 수집 (선택 기능) |

## 4. 데이터베이스 설계 (SQLite)

### 4-1. 테이블 관계

```
users ──< posts ──< comments
  │         
  ├──< favorites >── cards >── card_sets
  │                    │            │
  │                    └──< price_history
  │                                 └──< box_price_history
  ├──< price_reports (선택)
  └──< portfolio (선택) >── cards
```

### 4-2. users (회원)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 회원 번호 (자동 증가) |
| username | TEXT UNIQUE | 로그인 아이디 |
| password_hash | TEXT | bcrypt 해시 |
| nickname | TEXT | 닉네임 |
| role | TEXT | `user` / `admin` |
| status | TEXT | `active` / `banned` |
| created_at | DATETIME | 가입일 |

### 4-3. card_sets (카드 세트)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 세트 번호 |
| name | TEXT | 세트명 |
| release_date | DATE | 발매일 |
| box_price | INTEGER | 박스 정가(소비자 원가) |
| packs_per_box | INTEGER | 박스당 팩 수량 |
| image_url | TEXT | 세트·박스 이미지 주소 (외부 URL, 없으면 대체 이미지) |

- **팩 정가 = box_price ÷ packs_per_box** (DB에 저장하지 않고 계산)

### 4-4. cards (카드)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 카드 번호 |
| set_id | INTEGER FK | 소속 세트 (card_sets.id) |
| name | TEXT | 카드명 |
| card_number | TEXT | 세트 내 카드 번호 |
| rarity | TEXT | 희귀도 |
| image_url | TEXT | 이미지 주소 (외부 카드 데이터 API의 이미지 URL, 없으면 대체 이미지) |
| created_at | DATETIME | 등록일 |

### 4-5. price_history (카드 시세 이력)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 이력 번호 |
| card_id | INTEGER FK | 카드 (cards.id) |
| price | INTEGER | 시세 |
| recorded_at | DATE | 기준 날짜 |
| source | TEXT | `seed` / `admin` / `report` / `auto` |

- (card_id, recorded_at) 인덱스를 생성해 기간별 조회 속도를 확보한다.

### 4-6. box_price_history (박스 시세 이력)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 이력 번호 |
| set_id | INTEGER FK | 세트 (card_sets.id) |
| price | INTEGER | 박스 시세 |
| recorded_at | DATE | 기준 날짜 |

### 4-7. favorites (찜)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| user_id | INTEGER FK | 회원 |
| card_id | INTEGER FK | 카드 |
| created_at | DATETIME | 등록일 |

- (user_id, card_id) 복합 기본키로 중복을 방지한다.

### 4-8. posts (게시글)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 글 번호 |
| user_id | INTEGER FK | 작성자 |
| category | TEXT | `free` / `price` / `brag` / `notice` |
| title | TEXT | 제목 |
| content | TEXT | 내용 |
| views | INTEGER | 조회수 (기본 0) |
| created_at | DATETIME | 작성일 |
| updated_at | DATETIME | 수정일 |

- `notice`(공지)는 관리자만 작성할 수 있다.

### 4-9. comments (댓글)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 댓글 번호 |
| post_id | INTEGER FK | 게시글 (삭제 시 함께 삭제) |
| user_id | INTEGER FK | 작성자 |
| content | TEXT | 내용 |
| created_at | DATETIME | 작성일 |

### 4-10. price_reports (거래가 제보, 선택 기능)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 제보 번호 |
| card_id | INTEGER FK | 카드 |
| user_id | INTEGER FK | 제보자 |
| price | INTEGER | 제보 가격 |
| created_at | DATETIME | 제보일 |

### 4-11. portfolio (내 포트폴리오, 선택 기능)
| 컬럼 | 타입 | 설명 |
|------|------|------|
| id | INTEGER PK | 보유 내역 번호 |
| user_id | INTEGER FK | 소유 회원 (users.id) |
| card_id | INTEGER FK | 카드 (cards.id) |
| quantity | INTEGER | 보유 수량 |
| purchase_price | INTEGER | 개당 매입가 |
| created_at | DATETIME | 등록일 |

- 같은 카드를 다른 가격에 여러 번 산 경우를 위해 한 카드에 여러 행을 둘 수 있다.
- 조회·수정·삭제는 항상 로그인한 본인의 데이터(`user_id`)만 대상으로 한다.

## 5. 시세 계산 로직

| 항목 | 계산 방식 |
|------|----------|
| 현재 시세 | `price_history`에서 해당 카드의 가장 최근 `price` |
| 기간 그래프 | 선택 기간(1주/1개월/3개월)의 `recorded_at ~ 오늘` 데이터 |
| 최고/최저/평균 | 선택 기간 데이터의 MAX / MIN / AVG |
| 박스 상승률 | `(박스 현재 시세 − box_price) ÷ box_price × 100` |
| 팩 환산 | 카드 현재 시세 ÷ 팩 정가 → "팩 N개 값" |
| 기간 상승률 | `(현재 시세 − 기간 시작 시세) ÷ 기간 시작 시세 × 100` |
| 평가금액 (선택) | 보유 카드별 `현재 시세 × quantity`의 합계 |
| 손익·수익률 (선택) | 손익 = 평가금액 − Σ(`purchase_price × quantity`), 수익률 = 손익 ÷ 총 매입금액 × 100 |

## 6. 인증 및 권한 설계

- **로그인 방식**: `express-session`으로 서버 세션을 사용한다. 세션 쿠키는 `httpOnly`, `sameSite` 옵션을 적용한다.
- **비밀번호**: bcrypt로 해시해서 저장하며 평문은 저장하지 않는다.
- **미들웨어**
  - `requireLogin`: 로그인하지 않은 경우 401 응답
  - `requireAdmin`: `role`이 `admin`이 아닌 경우 403 응답
- **정지 회원**: `status`가 `banned`이면 로그인을 차단한다.
- **작성자 검증**: 게시글·댓글 수정/삭제 시 작성자 본인 또는 관리자인지 확인한다.
- **본인 데이터 검증**: 포트폴리오·찜은 로그인한 본인의 데이터만 조회·수정·삭제할 수 있다.
- **관리자 계정**: `seed.js`에서 초기 관리자 계정을 생성한다.
- **보안**: SQL은 prepared statement로 실행하고, 화면 출력 시 사용자 입력을 이스케이프해서 XSS를 방지한다.

## 9. 초기 데이터 (seed)

- 관리자 계정 1개
- 카드 세트 2~3개 (박스 정가, 박스당 팩 수량 포함)
- 카드 20~30장, 카드별 3~6개월치 샘플 시세 (카드 정보와 이미지 URL은 공개 카드 데이터 API에서 가져오거나 직접 입력)
- 세트별 샘플 박스 시세
- 샘플 게시글과 댓글

## 10. 카드팩 개봉 시뮬레이션

- 기획서에 정의한 부가 기능으로, **현재는 기획 단계이며 구현 여부는 고려 중**이다.
- 구현하기로 결정하는 경우 기존 `users`, `cards` 구조와 연동하는 방향으로 별도 설계한다.
- 이 설계서의 테이블과 API에는 포함하지 않는다.

## 11. 확장 고려 사항

- 자동 시세 수집 (node-cron 스크립트, 실패 시 기존 DB 데이터 유지)
- 회원 거래가 제보 기능 (설계 포함, 구현은 선택)
- 내 포트폴리오 기능 (설계 포함, 구현은 선택)
- 게시판 이미지 첨부
