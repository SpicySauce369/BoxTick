# 추가 합의사항

`/docs`의 `웹사이트기획.MD`, `웹사이트설계.MD`, `웹사이트디자인.MD` 이후 GPT·Claude와 논의해 확정한 사항이다.
**이 문서가 BoxTick 구현 방침의 Source of Truth이며, 기존 3개 MD와 충돌하면 이 문서를 따른다.**
새 합의가 생기면 이 파일을 갱신하고, 맨 아래 변경 이력에 한 줄 남긴다.

---

## 1. 과제의 목적

실제 서비스가 아니라 **대학 웹 프로그래밍 과제**다. 교수는 AI 사용을 허용하고 권장한다.

교수 요구사항
- SQLite 사용
- Node.js 웹서버 사용
- 회원 기능
- 게시판 기능
- 일반 사용자 / 관리자 구분
- 기획을 실제 웹사이트로 구현
- 테스트 포함
- 구현된 중요 화면 약 10장 전후를 캡처해 PPTX로 제출

최종 제출물
- 프로젝트 폴더 전체 ZIP
- `캡처.pptx`

실서비스 수준의 대규모 데이터, 운영 인프라, 실시간 크롤링보다
**안정적인 실행, 기능 완성도, 테스트 가능성, 화면 완성도**를 우선한다.

## 3. 외부 API 및 데이터 전략

### 카드 정보
- TCGdex를 카드 기본정보·이미지의 **참고/수집용**으로 사용한다.
- 사이트 실행 중에는 TCGdex에 의존하지 않는다. 인터넷이나 외부 API에 장애가 있어도 핵심 기능이 동작해야 한다.
- 데이터 흐름: `TCGdex → import/seed → SQLite → Express API → Browser`
- 분리 구조
  - `data/cards.seed.json`: 제출용 seed 데이터 (Git에 커밋)
  - `scripts/import-tcgdex.js`: 선택 도구. 사이트는 SQLite만 조회한다.
- `cards.external_id`, `card_sets.external_id`(UNIQUE)로 TCGdex ID를 저장하고, `UNIQUE(set_id, card_number)`로 seed 중복을 막는다.

### 카드 시세
- 실제 거래 시세 API에 의존하지 않는다.
- `price_history`에 과제용 샘플 시계열 데이터를 넣어 다음을 구현한다.
  - 현재가
  - 1주 / 1개월 / 3개월 변화
  - 최고가 / 최저가 / 평균가
  - Chart.js 그래프
- 사이트에 다음 취지의 안내를 표시한다.
  > 본 프로젝트의 시세 데이터는 기능 구현 및 테스트를 위한 샘플 데이터이며 실제 거래 가격을 보장하지 않습니다.

### 박스 시세
- 카드 박스 시세 조회도 중요 기능이다.
- 네이버 쇼핑 검색 API는 2026-07-31에 종료됐고, 네이버 Commerce API는 판매자 본인 상품 관리용이라 쓸 수 없다. 다나와 공개 Open API도 종료됐다.
  → **네이버·다나와를 실시간 API로 호출하지 않는다.**
- 네이버·다나와·카드샵 가격을 참고해 관리자가 대표 시세를 `box_price_history`에 입력한다. 샘플 데이터도 이 테이블에 넣는다.
- `box_price_history` 컬럼: `id`, `set_id`, `price`, `recorded_at`, `source`, `source_url`, `seller_name`
- `source` 값: `seed`, `admin`, `naver-reference`, `danawa-reference`, `cardshop-reference`, `other`

## 4. 데이터 규모

과제 데모 기준이며, 대규모 카드 DB는 만들지 않는다.
- 카드 세트 약 3~4개
- 카드 약 20~30장
- 카드별 가격 이력 약 3~6개월
- 박스 가격 이력
- 샘플 사용자, 관리자 1명
- 샘플 게시글 / 댓글

화면을 캡처했을 때 빈 화면이 나오지 않도록 샘플 데이터를 풍부하게 넣는다.

## 5. 디자인 방향 (기존 디자인 MD 보완)

기존 디자인 MD의 기본 원칙은 유지하되, **Pokémon Sword / Shield UI의 화면 구조와 시각 문법을 적극적으로** 가져온다.
"영감을 받은 일반 웹사이트" 수준보다 더 강하게 적용한다.

사용 가능한 요소
- 대각선 패널, 비대칭 화면 분할
- 청록 / 마젠타 / 노랑 포인트 (배경 전체를 원색으로 칠하지는 않는다 — 아래 확정 규칙 참고)
- 굵은 제목, 흰색 정보 패널
- 둥근 선택 메뉴, 원형 메인 메뉴
- 도감형 목록, 상태창형 카드 상세, 가방 메뉴형 박스 시세
- Y-COMM 느낌의 게시판
- 게임 하단 버튼 안내 UI
- 선택 항목 강조, 게임 메뉴식 화면 전환 느낌

화면별 대응
| 화면 | 스타일 |
|------|--------|
| 메인 | Sword/Shield 메인 메뉴 |
| 카드 목록 | Pokédex |
| 카드 상세 | Pokémon 상태창 |
| 박스 시세 | Bag/아이템 화면 |
| 게시판 | Y-COMM |
| 관리자 | Bag/Settings 계열 UI를 웹 관리화면에 적용 |

금지: 실제 게임에서 추출한 아이콘, 로고, 원본 UI 이미지, 폰트 파일, 텍스처.
HTML/CSS와 직접 만든 SVG·도형으로만 구현한다.

시세 색상 규칙은 유지한다.
- 상승: 빨강 계열 + ▲
- 하락: 파랑 계열 + ▼
- 색상만으로 의미를 전달하지 않는다.

### 확정 디자인 규칙 (PR #7, 사용자 확정)

공통 기반은 `public/css/base.css`, `public/js/common.js`에 있고, **`/styleguide.html`이 사용자가 확정한 디자인 샘플**이다.
페이지 UI는 이 샘플의 primitive를 조합해서 만들고, 공통 CSS의 확정된 모양은 바꾸지 않는다.
실제 Sword/Shield 화면(메인 메뉴, 상태창, 기술, 가방, 박스)의 문법을 참고했다.

**컬러 · 폰트**
| 용도 | 값 |
|------|-----|
| Sword Cyan | `#00A6C8` (`--sword`) |
| Shield Magenta | `#E52B70` (`--shield`) |
| Signal Yellow | `#FFD447` (`--signal`) |
| Deep Navy | `#171A24` (`--navy`) |
| Off White | `#F7F7F4` (`--off-white`) |
| 상승 | `#E5484D` + ▲ (`--price-up`) |
| 하락 | `#3E63DD` + ▼ (`--price-down`, 다크 모드는 `#7B96F0`) |
| 선택·헤더·조작 바 | 검정 잉크 `#18181C` (`--ink`) |

- 폰트는 CDN 없이 시스템 폰트 스택을 쓴다: `"Segoe UI", "Noto Sans KR", "Malgun Gothic", "Apple SD Gothic Neo", sans-serif`

**바탕과 대각선 띠**
- 모든 페이지의 바탕은 같은 밝은 회백색 `#EEF0F3`이다. **배경 전체를 원색으로 칠하지 않는다.**
- 페이지마다 바뀌는 것은 **가운데 큰 대각선 띠의 색(연하게)과 강조색뿐**이다: `<body data-stage="sword | shield | signal | neutral">` (기본 `sword`)
- 띠 색 권장: 카드 `sword` / 박스 `signal` / 커뮤니티 `shield` / 관리자 `neutral`
- 띠의 각도와 폭은 1024px · 700px에서 바뀐다. 모바일에서는 띠를 세워 화면 가운데를 지나가게 한다.
- 다크 모드는 어두운 바탕에 같은 띠를 연하게 깐다.

**선택 표시**
- 선택된 항목은 **검정 알약 + 흰 글자 + 왼쪽 바깥의 굵은 검정 `>`** 로 표시한다. 강조색으로 채우지 않는다.
- 다크 모드에서는 흰 알약 + 검정 글자로 반전한다.
- `.is-selected`, `aria-selected`, `aria-current`, `aria-pressed`가 모두 같은 모양이다.

**primitive (base.css)**
| 클래스 | 용도 (참고한 게임 화면) |
|--------|------------------------|
| `.list` / `.list-row` | 흰 알약 행 목록 (기술 목록, 가방 목록) |
| `.list-row__aside` | 행 오른쪽 짙은 회색 값 캡슐 (기술 PP 자리 → 시세) |
| `.list-heading` | 목록 위 소제목 띠 (가방 "TMs" 띠) |
| `.stat-table` | 회색 라벨 칸 + 흰 값 칸 표 (박스 화면 능력치 표) |
| `.panel` / `.panel-head` | 흰 패널 / 패널 상단 검정 띠 (상태창 이름 띠) |
| `.circle-menu` / `.circle-item` | 흰 원 아이콘 + 라벨 메뉴 (메인 메뉴) |
| `.info-bar` | 반투명 검정 알림 띠 (메인 메뉴 알림). 토스트도 같은 모양 |
| `.round-select` | 알약 탭·필터 |
| `.stepper` | `◀ 값 ▶` 넘기기 (박스 번호) |
| `.chip` | 희귀도·카테고리 표시 |
| `.page-title` | 흰 원 아이콘 + 굵은 제목 |
| 하단 조작 바 | 화면 맨 아래 검정 바 (`Ⓐ 결정  Ⓑ 돌아가기`). `BoxTick.initPage({ hints })`로 그린다 |

**원형 메뉴 열 수 (`.circle-menu`)**
- Desktop: 5열 (가용 폭을 나눔)
- Tablet: 4열 (가용 폭을 나눔)
- Mobile: 2열, `132px` 고정 열 + 가운데 정렬

**접근성 · 렌더링**
- 버튼·행·메뉴·입력은 최소 44px이다. `:focus-visible`은 노란 링 + 검정 외곽선으로 표시하고, `prefers-reduced-motion`을 존중한다.
- 사용자 입력(글·댓글·닉네임)은 `BoxTick.el()` / `setText()`로 텍스트로만 넣는다. innerHTML로 넣지 않는다.

## 7. 실행 재현성

교수가 ZIP을 받아 아래 순서만으로 실행할 수 있어야 한다.

```
npm install
npm run db:init
npm test
npm start
```

- `npm run seed`를 따로 제공해도 좋다.
- SQLite DB 파일은 Git에 커밋하지 않는다. `.gitignore`에 최소 `node_modules/`, `.env`, `*.db`, `*.sqlite`, `*.sqlite3`를 포함한다.
- `.env.example`은 제공하되 실제 비밀값은 커밋하지 않는다.

## 8. 테스트

`node:test` + `supertest`를 사용한다. 최소 테스트 항목은 다음과 같다.
- 회원가입 성공 / 중복 아이디 실패
- 로그인 성공 / 잘못된 비밀번호 로그인 실패
- 비로그인 보호 API 접근 401
- 일반 사용자 관리자 API 접근 403 / 관리자 접근 성공
- 게시글 작성, 게시글 수정·삭제 작성자 권한, 댓글
- 카드 목록 / 카드 상세 / 카드 가격 이력
- 박스 목록 / 박스 가격 이력
- 존재하지 않는 데이터 404

## 9. 보안 / 권한

과제 수준이라도 아래 항목은 제대로 구현한다.
- bcrypt 비밀번호 해싱
- express-session, httpOnly 세션 쿠키, sameSite 설정
- `requireLogin`, `requireAdmin`
- 게시글 수정·삭제 시 작성자 확인, 공지 작성은 관리자만
- 사용자별 데이터 접근 제한
- SQL parameter binding
- 기본적인 입력 검증, 출력 시 XSS 고려
- banned 사용자 로그인 차단

세션 저장소는 메모리 기반도 허용한다.
회원 탈퇴는 hard delete보다 `status='banned'`를 우선 사용한다. 스키마의 CASCADE 구조는 유지한다.

## 10. 관리자 기능

관리자 페이지는 PPT 캡처의 중요 화면이다. 최소 기능은 다음과 같다.
- 카드 관리, 세트 관리
- 카드 가격 등록, 박스 가격 등록
- 회원 조회 / 상태 관리
- 게시글 관리, 공지 작성

가격 등록 UI에서는 대상, 가격, 기준 날짜, 출처, source URL을 입력할 수 있게 한다.

## 12. GitHub 작업 방식

- 저장소: `SpicySauce369/BoxTick`, 기본 브랜치: `main`
- GPT와 Claude가 동시에 개발하므로 **같은 파일을 동시에 수정하지 않는다.**
- 진행 순서: 기능별 브랜치 → 구현 → PR → 상대 AI 리뷰 → merge
- `main`에 직접 큰 변경을 넣지 않는다.
- 기존 `/docs` 3개 파일은 별도 요청이 없으면 수정하지 않는다. 새 합의는 이 파일에 반영한다.

## 13. 구현 철학

> **기능은 적더라도 모두 제대로 동작하는 것.**

교수가 ZIP을 열었을 때 다음이 명확히 보여야 한다.
- 설치와 실행이 된다.
- DB가 작동한다.
- 회원 기능, 게시판, 사용자/관리자 구분이 작동한다.
- 카드·박스 시세가 작동한다.
- 테스트가 통과한다.
- 화면 완성도가 높다.
